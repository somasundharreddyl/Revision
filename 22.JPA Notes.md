1.EntityManager is created for each HTTP Request, different methods in same Http Request share the same Entity Manager.

2.Dispatcher Servlet creates Entity Manager in prehandle Method.

3.While adding data(Post(.save()),it must pass through Entity Manager,persist in it and move to DB.



* **2nd level Caching:**



1.Data is directly inserted into DB.

2.During get() call, Cache miss happens and fetch data from DB and persist in 2nd level cache.

3.CacheConcurrencyStrategy.Read\_ONLY : throws error if update happens.

4.CacheConcurrencyStrategy.Read\_Write: read operation put shared lock on 2nd cache.multiple read operations happens parallely.

&nbsp;                                      Update operation put exclusive lock on cache and invalidate cache.No Read nor Write.After update happened in db \& commit,

&nbsp;                                      It update cache with latest data \& remove invalidate flag.

5.CacheConcurrencyStrategy.NONSTRICT\_Read\_Write: read operation does not put any shared lock on 2nd cache.multiple read operations happens parallely.

                                       Update operation does not put exclusive lock on cache.It invalidate cache.After update happened in db \& commit,

                                       It does not update cache with latest data.If Get() operation happens,due to invalidate flag it directly read from db \& update cache data while

&nbsp;                                      returning.
